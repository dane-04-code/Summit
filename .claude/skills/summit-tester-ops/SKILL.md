# Summit Tester Operations

Read `docs/GO_TO_MARKET_PLAN.md`. Focus on technically capable iPhone users who already run Hermes and can install/enable the Summit plugin.

## Cohort workflow

1. Admit small cohorts: 3 friendly-alpha users, then 5–8 private-beta users, then 12–20 total release-candidate users.
2. Guide one normal streamed turn, background/reopen recovery, eligible notification routing, and normal two-to-three-day use.
3. Capture only the minimum diagnostic context: visible error, app/iOS/plugin version, host OS, and network context. Do not request credentials, pairing codes, raw agent output, or unredacted transcripts.
4. Classify P0 privacy/security, P1 core loop unavailable, P2 confusing/degraded, P3 polish. Stop widening for P0/P1.
5. Convert repeated friction into a specific documentation or product change, then retest it.

## Output

Return cohort state, funnel metrics, issues grouped by severity/repetition, tester-safe follow-ups, and a widen/hold recommendation.
